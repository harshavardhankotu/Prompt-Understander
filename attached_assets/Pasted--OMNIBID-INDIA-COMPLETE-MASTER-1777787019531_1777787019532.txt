WHAT WE ARE BUILDING:
A Real-Time Reverse Auction Marketplace where users post problems 
and verified service providers compete to solve them. Price goes DOWN, 
not up. WhatsApp is the primary interface for rural/Bharat users. 
UPI Escrow is the payment backbone. The platform covers 3 tiers:
Retail (B2C) → SME/B2B → Enterprise (Limber UK-inspired).

THIS IS NOT A DIRECTORY LIKE JUSTDIAL.
This is a "Real-Time Solutions Exchange."

═══════════════════════════════════════════════════════════════════
TECH STACK — DO NOT DEVIATE
═══════════════════════════════════════════════════════════════════

Frontend:     React + TailwindCSS (mobile-first, 80% users on phone)
Backend:      Node.js + Express
Database:     Replit PostgreSQL

PHASE 3 — CORE FEATURES (Build in this exact order)
═══════════════════════════════════════════════════════════════════

STEP 1: "Post a Problem" Flow
  - Category dropdown (20 sectors from seed data)
  - Selecting a category dynamically renders its JSONB custom_fields
  - Each field type inferred from name (number for tonnage, date for travel_date, etc.)
  - Toggle: "Make this a Mega Project" (unlocks sub-task input)
  - Toggle: "Start a Society Syndicate" (generates shareable link)
  - Toggle: "I don't know the category — just describe my problem" (Jugaad mode)
  - Max Budget + Auction Duration (dropdown: 30min / 2hr / 6hr / 24hr / 72hr)
  - File upload for supporting docs
  - Language selection for the post
  - Preview before submit

STEP 2: Live Bid Feed (Provider side)
  - Real-time feed via Socket.io — new requirements appear without refresh
  - Filter by: Category, City, Budget range, Auction time remaining
  - Cards show: Title, max budget, time left (countdown), bids received count
  - "Bid War" badge fires when 5+ bids arrive on a requirement
  - "BULK DEAL" badge on syndicate requirements with participant count shown
  - "Jugaad" badge for symptom-only posts
  - Sorted by: Newest / Ending soon / Highest budget
  - Provider can "Save" a requirement and get a WhatsApp alert reminder

STEP 3: Bidding Interface
  - Bid amount (must be ≤ current lowest bid OR justify why)
  - Message / pitch (500 char max)
  - Proof of Work: "How many similar jobs have you completed?"
  - Estimated start time (dropdown: Now / In 1 hour / In 4 hours / Tomorrow)
  - Toggle: "I am returning empty / have a cancellation slot" (Backhaul / Empty Slot badge)
  - Sub-task selection (for Mega Projects — bid on one task only)
  - Crew size offered (Agency providers)
  - "Highlight my bid" — pay ₹50 to pin to top (shown in amber border)
  - Two-Envelope: If requirement.bid_type = 'two_envelope', show 
    Envelope A upload first. Financial amount locked until buyer approves technical bid.
  - WhatsApp bidding: POST /api/webhooks/whatsapp accepts provider's phone + reply amount

STEP 4: Buyer Bid Dashboard
  - Live list of all bids on their requirement (updates via WebSocket)
  - Sort: Lowest price / Highest Trust Score / Fastest start / Network match
  - "Jaan-Pehchaan" badge: Green badge on bid card if provider has been 
    hired by anyone in buyer's contact list (query user_contacts hash match)
  - "Trusted by your contact" — do not show the contact's name, just "1 connection in network"
  - For two-envelope: "Approve Technical" button per bid. Financial amount 
    hidden until clicked.
  - Accept Bid button → triggers:
    1. Auction closes
    2. Bhaav-Taav room opens (if buyer wants)
    3. UPI payment modal fires
    4. WhatsApp pre-filled connect link generated
    5. Auto-generated Work Order PDF created (Aadhaar eSign prompt)
    6. Requirement status → 'accepted'

STEP 5: Bhaav-Taav Negotiation Room
  - Unlocks after auction ends, between buyer and top 3 lowest bidders only
  - Real-time chat via Socket.io
  - Special button: "Make Final Counter-Offer" — sends a counter amount 
    as a special message bubble with Accept / Decline buttons for provider
  - Time limit: 15 minutes. After that, highest bid in room auto-wins if no deal
  - Only ONE counter-offer allowed per buyer per provider in the room

STEP 6: UPI Escrow Payment Flow
  - Triggered on bid acceptance
  - Mock Razorpay modal: QR code placeholder + UPI ID input + "Pay Now"
  - On simulated payment:
    * Requirement status → 'in_progress'
    * Payment record created: total, platform_fee (per category %), 
      TDS (2% if > ₹30,000), net_to_provider
    * Mobilization advance % (if declared in bid) released immediately to provider
    * Remaining held in escrow
  - Work Proof Upload (provider): Photo + notes per milestone
  - Buyer approves → milestone amount releases to provider UPI
  - Full release only when all milestones approved
  - If disputed → payment frozen, dispute record created

PHASE 5 — WHATSAPP INTEGRATION (Backend Logic)
═══════════════════════════════════════════════════════════════════

POST /api/webhooks/whatsapp
  - Receives: provider phone number + message text (a number = bid amount)
  - Logic:
    1. Hash the phone → find user in users table
    2. Find the most recent open requirement they were alerted about 
       (stored in notifications.metadata)
    3. Validate: bid amount > price floor, provider compliance_score ≥ 50
    4. Insert bid into bids table with bid_source = 'whatsapp'
    5. Emit Socket.io event → buyer dashboard updates live
    6. Reply to provider via WhatsApp: 
       "Bid of ₹[amount] submitted for [job title]. You are currently 
       [rank] of [total] bids."

NOTIFICATIONS THAT TRIGGER WHATSAPP ALERTS:
  To providers (when requirement posted near them):
  "New [category] job in [city]. Budget: ₹[max]. Ends in [time]. 
   Reply with your bid amount OR visit [link]"
  
  To buyers (when bid received):
  "New bid from [Provider Name] (Rating: X/5, Verified). 
   Bid: ₹[amount]. View all bids: [link]"
  
  To both (when bid accepted):
  Pre-filled connect link: 
  "wa.me/91[provider_phone]?text=Hi, I accepted your OmniBid for [title]. 
   Let's confirm the details."
