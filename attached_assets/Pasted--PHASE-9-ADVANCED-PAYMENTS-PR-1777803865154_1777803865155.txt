PHASE 9 — ADVANCED PAYMENTS, PROCUREMENT, ANALYTICS, AND HYPERLOCAL INTELLIGENCE
═══════════════════════════════════════════════════════════════════

Build these features as role-based modules for the 4 user types already defined:
1. retail_buyer
2. enterprise_buyer
3. solo_provider
4. agency_provider

Do NOT expose every feature to every role.
Each feature must have:
- role visibility rules
- frontend screens
- backend APIs
- analytics events
- permissions
- test cases
- failure states

───────────────────────────────────────────
A. FINANCIAL & PAYMENT INFRASTRUCTURE
───────────────────────────────────────────

1. WhatsApp Pay Integration
- For retail_buyer: allow payment completion from WhatsApp chat after bid acceptance for eligible low-risk jobs
- For enterprise_buyer: show payment link / invoice handoff, but default to escrow and procurement flow
- For solo_provider and agency_provider: send payment received, escrow funded, and payout release notifications in WhatsApp
- Add eligibility rules: only supported transaction types, capped amount for MVP, compliance required
- Track events:
  - whatsapp_pay_initiated
  - whatsapp_pay_completed
  - whatsapp_pay_failed

2. UPI One World Interoperability
- Add support for international delegates/travel users who may not have local bank accounts
- Use lightweight verification and alternate payment eligibility checks
- Restrict availability by category:
  - enabled for travel, events, hospitality, selected enterprise cases
- Add fallback to standard escrow if unsupported
- Track:
  - upi_one_world_used
  - upi_one_world_failed
  - foreign_buyer_checkout_completed

3. Embedded Finance & Micro-Lending
- Extend Omni Score logic already in system
- For solo_provider:
  - offer small working capital loan after accepted bid or against verified escrow receivable
- For agency_provider:
  - offer mobilization advance / payroll bridge / fleet fuel advance
- For retail_buyer:
  - do not enable by default
- For enterprise_buyer:
  - no checkout loan, but allow invoice finance placeholder for future
- Credit model must use:
  - escrow history
  - dispute rate
  - completion rate
  - on-time proof submissions
  - verified earnings history
  - behavioral signals
- Track:
  - loan_offer_shown
  - loan_offer_accepted
  - loan_offer_declined
  - loan_disbursed

4. Real-time Fraud Detection
- Build AI/rule engine for:
  - abnormal bid velocity
  - duplicate devices/accounts
  - unusual payout routing
  - repeated bid withdrawal abuse
  - collusive bidding
  - suspicious location mismatch
  - rapid multi-account payment attempts
- Enterprise transactions should have stricter thresholds
- Fraud score should affect:
  - payout hold
  - additional verification
  - manual review
  - vendor ranking visibility
- Track:
  - fraud_flag_created
  - transaction_held_for_review
  - fraud_false_positive_cleared

───────────────────────────────────────────
B. SPECIALIZED AUCTION & PROCUREMENT MODELS
───────────────────────────────────────────

1. Limited Reverse Auctions
- Enterprise-only by default
- Optional premium mode for retail high-trust categories
- Only pre-qualified / empanelled vendors can participate
- Integrate with compliance score, trust score, and category license checks

2. Multi-Round Bidding
- Add bidding rounds:
  - round 1 qualification
  - round 2 revised pricing
  - round 3 final offer
- Buyer can configure:
  - number of rounds
  - invited vendors
  - round deadlines
- Best for enterprise_buyer and large agency_provider participation

3. Sealed Bid Auctions
- Financial offers hidden from competing vendors until open event
- Support for confidential procurement and sensitive categories
- Integrate with existing two-envelope logic

4. Multi-lot Management
- One requirement can contain multiple lots/tasks/regions/sites
- enterprise_buyer can create multiple lots in one auction
- solo_provider can bid on one lot
- agency_provider can bid on multiple lots
- lot-wise compliance, pricing, work proof, and payout must be tracked separately

───────────────────────────────────────────
C. ADVANCED DATA & ANALYTICS
───────────────────────────────────────────

1. Competitor Intelligence
- For providers:
  - show category-level market saturation
  - average winning bid range
  - bid density by city and time
  - recommended best bidding window
- Do NOT reveal competitor private identities or confidential sealed-bid values
- For enterprise buyers:
  - show supplier participation depth and regional supply availability

2. Post-Auction Analysis
- For retail_buyer:
  - savings vs max budget
  - time to first bid
  - completion confidence
- For enterprise_buyer:
  - vendor competitiveness
  - rate trend by category
  - award efficiency
  - compliance pass/fail ratio
  - lot-level sourcing insights
- For solo_provider / agency_provider:
  - win/loss reasons
  - pricing competitiveness
  - missed opportunity analysis
  - response speed impact

3. AI-Driven Vendor Ranking
- Ranking inputs:
  - compliance score
  - trust score
  - category-specific license validity
  - completion rate
  - dispute ratio
  - on-time start rate
  - proximity relevance
  - enterprise empanelment status
  - fraud risk score
- Different weightages by role and category
- enterprise_buyer can choose:
  - lowest cost
  - best compliance
  - fastest start
  - balanced ranking
- retail_buyer sees simplified labels:
  - Best Price
  - Trusted Choice
  - Fastest Available
  - Nearby Best Match

───────────────────────────────────────────
D. HYPERLOCAL & COMMUNITY FEATURES
───────────────────────────────────────────

1. Proximity-Based Personalization
- Extend proximity bid and local matching logic
- Rank providers using:
  - exact locality
  - service radius
  - past buyer behavior
  - repeat local provider preferences
  - category urgency
- Strongest for retail_buyer and solo_provider

2. GPS Real-Time Tracking
- After bid acceptance:
  - solo_provider can share en route status
  - agency_provider can share crew/vehicle route status
  - retail_buyer sees ETA
  - enterprise_buyer sees SLA tracking dashboard
- Required for logistics, home services, field support, events, fleet cases

3. Sustainability Tracking
- Compute reduced travel distance, route efficiency, and fuel/carbon estimate
- enterprise_buyer dashboard gets reporting exports
- logistics and agency_provider views show efficiency score
- retail_buyer sees simple message:
  - “shorter travel distance saved time and fuel”

───────────────────────────────────────────
ROLE-BASED FEATURE ACCESS RULES
───────────────────────────────────────────

retail_buyer:
- WhatsApp Pay: yes
- UPI One World: yes for travel/events/hospitality
- Limited reverse auction: optional, premium verified mode only
- Multi-round bidding: limited use
- Sealed bids: rarely shown
- Proximity personalization: high priority
- GPS tracking: yes
- Sustainability: lightweight summary only

enterprise_buyer:
- WhatsApp Pay: optional, secondary
- UPI One World: yes where relevant
- Limited reverse auction: core
- Multi-round bidding: core
- Sealed bids: core
- Multi-lot management: core
- Competitor intelligence: core
- Post-auction analysis: core
- AI vendor ranking: core
- GPS SLA tracking: core
- Sustainability reporting: core

solo_provider:
- Embedded finance: high priority
- Competitor intelligence: high priority
- AI ranking visibility: high priority
- Proximity personalization: high priority
- GPS tracking: yes
- Limited reverse auction access: only if qualified
- Multi-lot bidding: single-lot only

agency_provider:
- Embedded finance: high priority
- Fraud checks: strict
- Limited reverse auction access: core if qualified
- Multi-round bidding: core
- Sealed bids: core
- Multi-lot bidding: core
- Competitor intelligence: core
- GPS fleet/crew tracking: core
- Sustainability efficiency: important
